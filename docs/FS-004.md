# FS-004 — Local Profiles

Version: 0.4.0
Gate: LEVEL_A

## Scope
- Save the current discovery configuration as a local favorite profile.
- Quick-switch directly from favorites.
- Keep the 8 most recently used channel configurations, deduplicated newest-first.
- Keep up to 24 favorites, deduplicated by full discovery configuration.
- Export settings + local profiles as a versioned JSON backup.
- Import a Feed Switcher JSON backup after validation and normalization.
- Popup shows favorite/recent counts.
- No backend, account, sync service, YouTube Data API, or additional permissions.

## Storage
- `fs.settings.v1`: current extension/discovery settings (schema v4).
- `fs.profiles.v1`: offline-first profile store (schema v1).

Profile objects are deliberately separated from the UI so a later cloud-sync adapter can reuse the same domain model.

## Acceptance checklist
1. Upgrade from 0.3.1 to 0.4.0 and refresh an already-open YouTube tab once.
2. Configure a channel and click **收藏当前**. The profile appears immediately under **我的频道**.
3. Change Topic/language/region. The default favorite name follows the current configuration until the name is manually edited.
4. Click a saved favorite. Feed Switcher should navigate directly to that channel and add it to **最近使用**.
5. Enter several different channels. Recents should be newest-first and duplicate configurations should move to the front rather than duplicate.
6. Delete a favorite with `×`; other favorites and recent history remain intact.
7. Click **导出** and confirm a `feed-switcher-backup-YYYY-MM-DD.json` file is downloaded.
8. Delete/change some local profiles, then click **导入** and select the exported file. The saved configuration should be restored.
9. Try importing unrelated/invalid JSON. It must be rejected without corrupting current data.
10. Open the toolbar popup and confirm favorite/recent counts are shown.
11. Existing FS-003 Query Engine behavior remains unchanged.

## Limits
- Local only; clearing Chrome extension storage removes profiles unless exported first.
- Import currently restores the full Feed Switcher backup rather than merging two libraries.
- Cross-device/cloud sync is intentionally deferred to a later milestone.
