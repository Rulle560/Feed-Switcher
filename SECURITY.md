# Security and private data

Never attach synchronization keys, actual databases, personal profiles, browser history or .env files to public issues. Synthetic examples are sufficient for reproducing most failures.

If GitHub private vulnerability reporting is enabled, use that channel for a security report. If it is unavailable, request a private contact method without exposing exploit details or secrets publicly. No support address is invented by this release.

Only the current release is intended for maintenance. There is no guaranteed response-time commitment or audited production cloud service. The local development server binds to loopback; production authentication, abuse controls, service configuration and scheduled retention must be reviewed before public deployment.
